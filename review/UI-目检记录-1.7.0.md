## 可量化、可由代码/像素交叉核验的点

- 面板尺寸 400×520（`PanelMetrics.dropdown`），自检有断言。
- `PanelLayout.frames` 的头部 / 搜索 / 结果 / 底栏坐标，自检有断言。
- 图标：`Resources/MenuBarTemplate.png` 18×18 RGBA、可见像素只有 1 种 RGB `(0,0,0)`；
  `@2x` 36×36 同样单色；`AppIconSource.png` 1024×1024 sRGB with alpha；
  `iconutil -c iconset` 得 10 档；`plutil -lint Info.plist` OK。
- 头部表面色：`PanelPalette.surface` 返回 `calibratedWhite: 1`，alpha 浅色 0.66 / 深色 0.055。
- 自绘组件 `DropSurfaceView` / `SceneHeaderView` / `SceneBadgeView` / `ActivityStripView` /
  `TargetPillView` 继承 `PaletteRedrawView`，`viewDidChangeEffectiveAppearance()` 触发 `needsDisplay`。

## 第五轮：LOGO 重新设计（build 22）

用户反馈「图标感觉被压缩了」，要求简洁、适配界面显示。逐处核对后确认三个原因：

| 位置 | 旧实现 | 问题 |
| --- | --- | --- |
| 菜单栏 18pt | 纸张轮廓 + 折角 + 箭杆 + 三角，内容仅 12×15 | 1.7px 细线在 18px 下糊成一团 |
| 应用图标 | 896×896 底板 + 折角 + 两条内容线 + 渐变箭头 + 落点光 | 元素过密，16/32px 只剩一个白块 |
| 面板头部 40pt | SF Symbol `arrow.down.doc` | 系统符号自带留白，视觉偏小，且与图标不是同一造型 |

新标记只保留两个几何：**12 单位粗线 U 形托盘 + 悬在上方的向下箭头**（100×100 网格，x14…86 / y16…74）。
一处坐标三处复用：`Sources/LogoMark.swift`（面板 40pt 矢量）、`tools/make-icon.swift`（1024 图标与 18pt 模板）。

可量化结果：

- 应用图标底板改为 macOS 规范 824×824 / 圆角 185（旧 896/208 偏大）；标记按内容包围盒缩放，不再受 100 网格留白拖累。
- 菜单栏内容从 12×15 提到 **16×14，左右各留 1px**；`isTemplate` 反相后深浅都清楚。
- **16/32px 单独简化**：去掉箭杆、三角加宽到 40、托盘线宽 15，避免杆与内壁粘连。
- 真机截屏确认菜单栏图标：U 形左右等长、箭头居中、线条均匀、无变形（`/tmp/od-recheck/menubar-first.png` 为放大对照）。
- 面板 40×40 不再是系统符号，Retina 下按实际像素重绘。

浅/深各 21 张基线已用 build 22 重生成（`review/ui-1.7.0/`、`review/ui-1.7.0-dark/`）；自检 205/205、回归 56/56 不变。

仍需真机确认：Finder / 启动台里的图标观感（已 `lsregister -f` + `killall Finder` 刷新，系统缓存极少数情况下要注销一次），以及菜单栏在浅色菜单栏下的反相效果（本轮截图为深色菜单栏）。
