1 AI 从「一条链路」拆成三个场景

1.6.0 的 AI 只做一件事：把转写文字交给模型生成标题/摘要/标签。1.7.0 按投进来的到底是什么分流，其他类型一律沿用旧模板，不调用模型。

document · 文件

摘要概览

Markdown / TXT / CSV、有文字层的 PDF、现代 Office（只读解包 OOXML）、RTF、旧 .doc（textutil）先取出文字，再请求模型生成标题、摘要、标签。取文有 10 MiB 上限，超长截断并在结果里标记。

transcript · 转录

概览 + 润色分段 + 修错病语

除了标题/摘要/标签，还要一份润色后的正文：去掉口头赘余、分段、改常见错病语。润色稿写进正文，原始转写逐行放进 [!quote]- 原始转写 折叠块，可逐字还原。

image · 截图

识别画面内容做概览

首帧按 EXIF 方向摆正，最长边压到 2048（不够再 1600 / 1280）、JPEG 白底、≤4 MiB，以 image_url + detail: high 发给视觉模型；画面里清晰可辨的文字单独写进 [!quote]- 画面文字。

legacy · 其他

完全照旧

压缩包、音视频、文件夹、SVG、未知扩展名、扫描版 PDF 等直接走 1.6.0 的文件归档模板，一个 1.7 字段都不加，状态记 off（不是 skipped，因此不写 AI 埋点）。

润色稿不是照单全收

解析阶段逐项校验：非空、长度落在原文 55%–135%（短文本 ±40%）、URL / 连续数字 / 反引号代码 / 英文技术词等关键项不得丢失。任一项不满足就拒收这次润色并降级，正文保持原始转写，笔记照常入库。

AI 是装饰，不是闸门。关闭、没配 Key、超时、HTTP 4xx/5xx、返回不合规范、视觉模型不支持——一律降级为旧模板；成功但跳过时界面闪「已归档（AI 跳过）」，不报归档失败。整批投递共用一个 12 秒预算，按剩余项数公平分摊，单项卡住不会拖死整批，且全部 Filer / AI / 附件 IO 都在后台队列。

3 应用图标（build 22 重新设计）

为什么重做。上一版是「深色底 + 纸张 + 折角 + 内容线 + 渐变箭头 + 落点光」，元素太多：缩到 18pt 菜单栏只剩一团白块，16px 列表里几乎糊成方块，看起来就像被压缩过。新标记只保留两个几何——粗线 U 形托盘 + 悬在上方的向下箭头，箭头比开口窄一圈，小尺寸才有留白可辨。
ONE PATH

一套坐标，三处复用

100×100 设计网格定义在 Sources/LogoMark.swift 与 tools/make-icon.swift：LogoMark 负责面板 40pt 矢量绘制，生成器用同一组坐标输出应用图标与菜单栏模板，改一处三处同步。

APP ICON

按 macOS 规范收边

1024 画布里改用 824×824、圆角 185 的标准底板（旧版 896/208 偏大，在 Finder 里比邻居显大）。标记按内容包围盒缩放，不受网格留白影响。16/32px 单独简化：去掉箭杆、加宽三角，避免杆与内壁糊在一起。

MENU BAR

16×14、左右各留 1px

MenuBarTemplate.png / @2x.png 仍是 18pt 单色，isTemplate = true 由系统反相；内容不再只占中间 12×15，而是撑到 16×14，浅色/深色菜单栏都立得住。

PANEL

不再是系统符号

头部 40×40 原来用 SF Symbol arrow.down.doc，现在改成 LogoMark 矢量绘制：Retina 下按实际像素重绘，不依赖位图缩放，也不会因为符号自带留白显得小。

BUILD

缺资源就构建失败

build.sh 写入 CFBundleIconFile、复制三个必需资源并 plutil -lint；少任何一个直接 exit 1，不会出现「装完没图标但打包成功」。

4 不变量：1.6.0 的行为一处没破

  • 只新建笔记：文件 / 截图 / 转录统一走 ExclusiveNoteWriter，隐藏临时文件 + fsync + link(2) 原子发布，同名只追加 -2/-3，绝不覆盖。
  • 旧模板逐字一致：AI 关闭、失败、旧 done pending（没有润色稿）都保持 1.6.0 的字段与文案；只有真正走过转录场景才升级到 A6.3 的 AI: "模型（耗时）"。
  • pending 队列 / 看门狗 / 恢复去重保持原样；新增字段全为可选，旧 pending 缺键仍能解码并解释为 .transcript。
  • --target 缺值 exit 2、既有 UserDefaults 键、--ai-run <文字> 旧用法不变。
  • 一次投递的 ai 事件与 drop 事件共用 captureId，看板按 id 去重；天生 legacy 不写 ai 事件。
  • Key 仍存系统钥匙串；场景 CLI 用进程内 overrideConfig / overrideKey，不写偏好也不碰钥匙串。

5.1 交付前重新检查（第四轮）

用户要求「重新检查」。主代理另做一次独立复核，并让 Codex 在不采信此前任何结论的前提下做只读盲检。 盲检报出 1 个 P0 + 4 个 P1，主代理逐条核代码、跑复现后确认其中 4 条属实、润色稿一条需限定范围，全部修补：

  • P0 恢复查重误删未归档录音：判重键从「正文前 60 字」改为「整段原文」，命中后不再删音频；新增两段开头相同、结论不同不得误判的自检断言。
  • P1 截图源图先删：GUI / CLI 都改为只有「零失败 + 确有笔记」才删临时 PNG，失败时弹窗与 stderr 给出源图路径。实测构造归档失败，709 KB 源图完整保留。
  • P1 批量遇一个缺失文件整批中止：改为单项失败继续归档，退出码回到 0 / 1 / 3。修复前 rc=1 且 0 笔记，修复后 rc=3 且有效项已入库。
  • P1 Tab 焦点按钮无法键盘激活：两个药丸按钮补 acceptsFirstResponder 与焦点环高亮，Space / Return / Enter 显式分发到截屏、灵感、打开按钮。
  • P1 润色稿可能改写关键事实：关键项校验扩到所有数字串与中文星期 / 日期，「200元、周五 → 900元、周一」这类改写会被拒绝并降级回旧模板；人名机构名等语义事实无法用正则证明，仍以折叠的原始转写为准。

按用户反馈「UI 和 ICON 也没变」一并处理：本机 /Applications 里残留 1.3.8 旧版、~/Applications 才是 1.7.0， 且菜单栏进程可能仍在跑替换前的旧代码；已把新版装到 /Applications、重启进程并刷新图标登记，安装说明也加了「只保留一份」的提示。 深色「就绪」徽标对比度偏淡同步修正（文字最亮像素 179 → 224），浅 / 深各 21 张基线用最终二进制重生成。

6 已知限制

  • 视觉识别需要模型本身支持图片输入；不支持时（如 415）会降级成旧模板，笔记照常入库。
  • PDF 无文字层、或超过 10 MiB 的文本，按 legacy 处理，不做 OCR；有文字层但带页码 / 重复页眉的 PDF 也只做顺序拼接，不剥离页码与页眉，摘要可能受噪声影响。
  • XLSX 取文按 OOXML XML 顺序拼接共享字符串与单元格值，未还原工作表名、行列坐标、合并单元格语义；多表 / 复杂表格的摘要仅供参考，原始文件始终完整保留。
  • 截图识别会在启用 AI 且配置视觉模型时，把压缩后的 JPEG 发给模型；关闭 AI 或将视觉模型置空仍会走文字模型（可能不支持图片）——需要完全不发图片时请关闭 AI。
  • 转录润色只做形式校验：长度、URL、代码、所有数字串、中文星期 / 日期、英文技术词。人名、机构名、否定语气等语义事实无法用正则证明，可能被模型改写；笔记里的折叠「原始转写」始终是逐字原文，以它为准。
  • 本机（Mac mini）没有麦克风，录音链路只能用 --record-test / --ui-memo 验；真机录音请在 MacBook 上确认一次。
  • Tab 焦点环、Space / Return 激活按钮、面板外点击收起、深浅外观实时切换、Finder / 启动台图标呈现，仍需在真机上人工确认一次；离屏渲染只能证明静态布局与配色。
  • 同一台机器只保留一份 ObsidianDrop（/Applications 与 ~/Applications 二选一）。两份共用 Bundle ID 会出现两个菜单栏图标，且系统权限按路径记录，会反复失效。
  • 无公证签名（ad-hoc），首次运行需右键 → 打开手动放行。
