# ObsidianDrop 1.3.11（构建 15）— 录音先存文件，再按文件转写

一句话：**录音改回「先落盘」**。录音这一段只负责把声音写成文件，转写等文件写完再走
「转写音频文件…」那条已经验证过的路径。进度也不再挤在标题里，改成图标位置上的
圆环 + 中间大号百分比。

- 交付：`dist/ObsidianDrop-1.3.11.dmg`（246K）
- SHA-256：`4e57c3ddc3014f8007936f70b181b684815462cd175932e9decbc1d185f7582a`
- 已安装：`~/Applications/ObsidianDrop.app`（已重启为新版）

---

## 一、为什么会「录音转存不成功」

1.3.10 里录音是**边录边喂识别引擎**：tap 回调把每块音频直接 `yield` 给分析器。这条路有两个硬伤：

1. **引擎要先建好，而建引擎要等语音模型就绪**。首次使用时模型可能要下几分钟，
   这期间用户说完点「结束」，`runner` 还是 nil——音频从未被保存到任何地方，
   失败之后连重试的素材都没有。
2. **成败取决于喂入速度与分析速度的竞争**。实时录音时喂入是等速的（还好），
   一旦节奏被打乱（系统负载、设备切换、格式转换漏块），丢掉的块补不回来。

改成「先落盘」之后，这两条都不再成立：文件写成功与否与识别引擎无关，
识别失败也只是「文字没出来」，音频还在。

## 二、改了什么

### 1. 新增 `RecordingStore`：录音只写文件

- 写入格式**取自第一块 buffer 自己**（`AVAudioFile(forWriting:settings:commonFormat:interleaved:)`）。
  不能按设备查询的格式建文件——`write(from:)` 要求 buffer 格式与文件 `processingFormat`
  严格一致，不一致抛的是 ObjC 异常，Swift 接不住，直接 SIGABRT。
- 文件落 `~/Library/Application Support/ObsidianDrop/recordings/录音-YYYYMMDD-HHMMSS.caf`。
- 转写成功 → 删除；没转出字 / 转写报错 → **保留**，弹窗里给「在访达中显示录音」，
  可以双击播放确认里面有没有声音，也可以右键「转写音频文件…」再试一次。
- 启动时清掉 7 天前的残留，避免失败录音无声堆积。
- tap 块大小 2048 → 4096，减少写盘次数。

### 2. 录音会话不再建语音引擎

`start()` 只做三件事：探设备/要权限 → 建录音文件 → 起引擎收音频。
语音模型、识别服务、识别权限在这时候**一概不碰**，所以：

- 第一次装就有麦克风就能录，不用等模型；
- 模型没下完也照录；
- 识别权限没给也照录（结束时才提示去授权，音频已经留住）。

`stop()` → 关文件 → 用 `SpeechRunner.transcribeFile()`（`analyzeSequence` + 背压）
→ 进度回调用的是同一套 `TranscribeProgress`。

### 3. 进度改成「图标上的环 + 中心百分比」

| 位置 | 1.3.10 | 1.3.11 |
|---|---|---|
| 图标 | 静态「识别中」图标 | **进度环**，中心大字 `33%`；收尾阶段转圈 + `…` |
| 标题 | `识别中 3:12 / 12:00（27%）`（160pt 宽必截断） | `转写中` / `收尾中` / `准备中` |
| 副标题 | `已出 63 字 · 剩余音频 1 分 20 秒`（被中间省略截断） | `已出 63 字 · 剩 1:20` |
| 底部小字 | `已处理 27% · 本机转写…` | `本机转写，不上传` |

- 百分比读系统的 `volatileRange.end`（真实处理位置），不是估算。
- **收尾阶段故意不给百分比**：那时音频已经 100% 送完，给个 100% 只会让人以为卡住，
  改成转圈环 + 「已等 0:05」。

### 4. 顺带修掉的四个问题

| 问题 | 现象 | 处置 |
|---|---|---|
| `close()` 把采样率一起清掉 | 12 秒音频算出 0 秒 → 误判「没有录到音频」 | 采样率单独保存，关文件后仍可算时长 |
| 准备阶段「取消」是假的 | 录音已结束、会话已释放，点取消只闪一句「已取消」，后台照样转、照样落笔记 | 转写的所有阶段（含准备）统一按「转写中」渲染，按钮显示「稍候」 |
| 电平只认 float32 | 老声卡/VoIP 设备给 int16 时峰值恒为 0 → 误报「没听到声音」、0 字诊断误判「你没说话」 | `level()` 支持 int16/int32 |
| 关文件后 tap 仍可能有在途块 | 极端时序下会把同一路径的文件重建/截断 | `closed` 标志，关后一律忽略 |

## 三、验证（结论从实验来）

### 1. 新链路自检命令

```bash
ObsidianDrop --record-test <音频文件>
```

把音频按录音 tap 的方式（4096 帧一块）写进真实的录音目录，再按文件转写，输出：

```
· 写入 录音-20261104-203231.caf：180.0 秒 / 34564096 字节，写入失败 0 次
  · 回读 180.0 秒 · 转写 278 字
```

三种硬件格式都跑通：

| 输入格式 | 写入 | 回读 | 转写 |
|---|---|---|---|
| 48kHz 单声道 Float32（常见内置麦） | 13.0 秒 | 13.0 秒 | 184 字 |
| 44.1kHz 立体声 Int16（USB 麦/老声卡） | 13.0 秒 | 13.0 秒 | 181 字 |
| 96kHz 立体声 Float32（外置声卡） | 13.0 秒 | 13.0 秒 | 180 字 |
| 48kHz 单声道 Float32，**3 分钟真实会议录音** | 180.0 秒 | 180.0 秒 | 278 字 |

（同一段英文测试语音在三条格式下字数 184/181/180，差异来自声道下混，属正常。）

### 2. 排版用离屏渲染核对

```bash
ObsidianDrop --render-preview <目录>
```

输出 5 张 160×176 的 PNG（待机 / 录音中 / 转写 33% / 收尾 / 准备下载模型）。
靠它抓到并修掉两处：

- 副标题被 `byTruncatingMiddle` 截成「已出 63 字 ·...频 1 分 20 秒」；
- 准备阶段整句说明不显示——当时只渲染 `detail`，而准备阶段的话在 `headline` 里。

### 3. 测试

- 自检 `--self-test`：**88 项全通过**（新增 9 项：录音落盘与回读、关文件后不再写入、
  文件名不冲突、进度环语义、int16 电平）

## 四、还需要你在 MacBook Air 上确认

本机没有麦克风，**真实「按键录音」这一段我验不了**。请：

1. 先卸旧的，把 1.3.11 **拖进「应用程序」**再打开（别从 dmg 里直接双击）；
2. 点「灵感」，说 10 秒，点「结束」；
3. 预期：录音中图标随音量呼吸、计时在走 → 结束后图标位置出现圆环和百分比 →
   闪「灵感已归档」。

如果还是没有字，弹窗会告诉你属于哪一种，并且**这次录音已经存在本机**：

- 点「在访达中显示录音」，双击播放——有声但没字 = 语言包/识别问题；
- 全程没声音 = 输入设备/音量问题；
- 也可把弹窗里「复制诊断信息」的内容发我。

## 五、已知取舍

- **录音中不再显示实时文字**。这是「先落盘」的直接代价：实时出字必须边录边识别，
  而那正是这次要拿掉的耦合。用音量呼吸 + 计时替代「确认在收音」。
- 录音文件是**未压缩**的（CAF / 线性 PCM），48kHz 单声道约 11 MB/分钟，
  5 分钟上限约 57 MB；转写成功即删，失败保留 7 天。
- 首次使用时，模型下载会从「录音前」挪到「录音后」（在「准备中」阶段显示），
  录音本身不受影响。
