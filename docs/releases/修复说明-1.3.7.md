## 二、逐项根因与修法

### 1. 附件目录 / 项目文档目录的软链逃逸（P1）

**根因**：`file()` 只把「用户输入的目标」交给 `VaultGuard.resolve`，随后附件目录用
`vault.appendingPathComponent("附件").appendingPathComponent(月)` 单独拼出来，**没有再校验**。
项目目标的 `<项目>/文档` 同理。库里若已存在指向库外的同名软链，附件就被复制到库外，
而笔记正常写进库内 —— 正是 QA-002 想消灭的那种分裂状态。

**修法**：新增 `VaultGuard.ensureInside(_:vault:label:)`，对**任何**将要写入的目录做
「解析软链后仍在库内且不等于库根」的判定；笔记目录与附件目录都在 `createDirectory` **前后各校验一次**
（建后那次用于堵住「建目录过程中被换成软链」的窗口）。违反即整批拒绝，一个文件都不写。

### 2. `realPath` 对不存在的尾段不解析软链（连带的根因）

修第 1 项时自检直接抓到的：`resolvingSymlinksInPath()` 遇到不存在的路径会**整体放弃解析**。
于是 `库/附件/2026-11`（月份目录还没创建）返回的是未解析路径，
`附件` 这层软链被跳过 → 第一道校验误判「在库内」→ `createDirectory` 在库外建出目录 → 第二道才拦住。

**修法**：`VaultGuard.realPath` 改为「先向下找到最深的存在路径并解析，再把不存在的尾段拼回去」。
这样学校验发生在创建之前，库外连空目录都不会出现。

### 3. 笔记写失败后的孤儿附件（P1）

**根因**：`archive()` 先 `copyItem` 复制附件，再 `front.write` 写笔记；笔记写失败时直接抛出，
已复制的附件留在库里。`BatchReport` 只记 `failed=1`，调用方按失败项重试就会多出一份附件。

**修法**：笔记写入包 `do/catch`，失败时 `removeItem(dest)` 回收刚复制的附件，再抛
`FilerError.noteFailed`，错误文案明确写出「已回收已复制的附件，库内不留残留」。

### 4. 参数缺值 / 未知选项被当成成功（P1）

**根因**：`if let t = args.firstIndex(of: "--target"), t + 1 < args.count` —— 条件不成立就
**跳过赋值并继续**，`target` 沿用 `Cfg.storedTarget`（上次使用的目标），于是笔误变成了「投递到别的目录且返回 0」。
未知 `--xxx` 则完全不检查。

**修法**：CLI 先做参数体检，任一条不满足即 `exit 2` 且不写任何文件：
- 出现未知选项（不在 `--file/--target/--vault/--json` 内）；
- `--target` 缺值，或其值以 `--` 开头；
- `--vault` 缺值。

### 5. `--file` 传入符号链接（P2）

**根因**：`copyItem(at: src)` 复制的是链接本身，库里因此出现一个指向库外的软链；
`relPath` 判定失败后，笔记里的「文件」字段还写成了库外绝对路径。

**修法**：`archive()` 一开始就把源解析成真实对象（`resolvingSymlinksInPath`），
后续判断类型、取扩展名、`copyItem` 全部基于真实对象。归档结果是**独立副本**，
名字仍用用户传入的文件名，笔记里的「文件」字段是库内相对路径。

### 6. 文档与实现不符（P3）

1.3.6 说明里写「失败摘要同时写 stderr」，实现只在 stdout 输出汇总。
选择按实现更正文档（两者都写会让终端重复显示两遍），并在说明里标注更正原因。
程序化调用应看退出码或 `--json`。

## 五、仍然存在的风险（不当成已验收）

1. **QA-004 仍需人工复测**：`menuNeedsUpdate` 是 AppKit 运行时回调，自动化只能证明 delegate 已接、
   数据源能扫到新项目。请在应用运行中新建 `10-项目/X`，直接展开菜单看是否出现。
2. **TOCTOU 窗口未消除**：`ensureInside` 校验与 `copyItem` 之间若有人并发替换路径，理论上仍可绕过。
   个人本机场景风险低，但这不是原子操作。
3. **整批重试仍会产生副本**：退出码 3 已提示只重试失败项；若调用方整批重跑，成功项会按规则生成 `-2`。
   已回收失败项的附件，但成功项不做内容级去重。
4. **软链策略是「解析后判包含」**：库内软链指向库内另一目录仍允许；若要一律禁止需再加规则。
5. **极端文件系统故障未覆盖**：磁盘满、ACL、跨月边界、同步软件占用锁。
6. **语音转写端到端未验证**：本机缺 `en-US` 语音模型，`memo()` 的标签分支是用同源临时插桩构建验证的。
