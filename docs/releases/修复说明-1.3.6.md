## 二、逐项根因与修法

### QA-001 批量部分成功被报告为失败

**根因**：`Filer.file(_:target:)` 在循环里 `guard ... else { throw }`，第一个不存在的源文件直接抛出，
中断整批并丢弃已完成的 `out` 数组；CLI 捕获后统一 `exit(1)`，所以既看不到成功项，也无法区分"全失败"和"部分成功"。

**修法**：
- `Filer.file` 返回 `BatchReport{outcomes, failures}`，逐项 `do/catch`，单项失败只记录不中断；
- 新增退出码 `3` = 部分成功（`0` 全成功、`1` 全失败、`2` 用法错误）；
- 默认输出逐项 `✓ / ✗` + 原因 + 汇总行，新增 `--json` 输出结构化结果（`exit_code` 也在其中）；
- 汇总行只写 stdout（不重复写 stderr，避免终端里出现两遍）；程序化调用请看退出码或 `--json`。

> 更正（1.3.7）：本节原先写"失败摘要同时写 stderr"，与实现不符，已按实际行为改正。

### QA-002 自定义目标可逃逸测试库

**根因**：`file()` 里 `let noteDir = vault.appendingPathComponent(rel)` 直接拼接用户输入，
`../` 未被校验；而附件目录由 `vault.appendingPathComponent("附件")` 单独算出，永远在库内
→ 笔记写库外、附件留库内，形成分裂状态。

**修法**：新增 `VaultGuard.resolve(target:vault:)`，在**任何写入之前**统一校验：
1. 空、绝对路径、`~` 开头 → 拒绝；
2. 任何 `..` 路径段 → 拒绝；
3. 词法规范化后 `resolvingSymlinksInPath()` 再解析符号链接（对不存在的尾部只解析已存在前缀）；
4. 结果必须仍是库内路径且不等于库根，否则拒绝。
笔记目录与附件目录都由这一个返回值派生，不再是两条独立拼接路径。

### QA-003 非收件箱笔记被标记为「收件箱」

**根因**：frontmatter 模板里 `tags:` 硬编码 `- 收件箱`（`file()` 与 `memo()` 各一处），与目标无关。

**修法**：`ArchiveTarget.tag` 按 `kind` 生成——收件箱 / 项目 / 领域 / 资源；
自定义目录取去掉数字编号前缀的目录名（`40-归档` → `归档`）；
YAML 标量统一加引号，避免目录名带空格或冒号破坏 frontmatter。语音笔记同样改为 `[灵感, <目标标签>]`。

### QA-004 新建项目不能在同一菜单立即出现

**根因**：`rebuildMenu()` 只在启动和若干动作后调用，`statusItem.menu` 一旦设置就不会再重建；
菜单打开时没有任何刷新钩子，所以磁盘上新增的项目要等下一次 `rebuildMenu()` 才可见。

**修法**：`AppDelegate` 实现 `NSMenuDelegate`，「投递目标」子菜单挂 `delegate`；
`menuNeedsUpdate(_:)` 时调用 `populateTargets()` 重建列表（含选中态同步）。
菜单每次展开都会重新扫描 `10-项目/`。

### QA-005 附件位置提示遗漏月份目录

**根因**：`placeHint` 是写死的字符串 `` `附件/` ``，没有拼月份；实际落盘路径却是 `附件/yyyy-MM/`。

**修法**：改为从实际产物路径取父目录（`(destRel as NSString).deletingLastPathComponent`），
提示与实际落盘位置不可能再脱节；项目目标同理显示 `<项目>/文档/`。

## 五、剩余风险与复测建议

1. **QA-004 未经真实 UI 操作验证**：自动化只覆盖"数据源可扫到新项目"与"委托钩子存在"，
   `menuNeedsUpdate` 的实际触发属于 AppKit 运行时行为，需人工复测：运行中新建 `10-项目/X`，直接展开菜单确认出现。
2. **重试仍可能产生重名副本**：部分成功时退出码 3 已提示只重试失败项，但若调用方仍整批重跑，
   成功项会按既有规则生成 `-2` 副本。未做内容级去重（属产品取舍，改动面较大）。
3. **`--json` 为新增接口**：旧调用方不受影响，但从未使用过结构化输出的脚本需按新字段名适配。
4. **符号链接判断基于解析后的真实路径**：库内软链指向**库内**另一目录仍被允许（视为合法目录），
   若产品要求一律禁止软链，需要再加一条"路径中不得出现软链"的检查。
5. **版本号已提升至 1.3.6**：复测请以 1.3.6 为准，避免与 1.3.5 产物混淆。
6. 截图三种模式、中文/空音频转写仍属验收报告列出的环境受限项，本次未覆盖。
