# ObsidianDrop 1.3.15 修复说明

> 2026-11-05｜只改命令行行为，不动界面与归档逻辑
> 起因：重写《应用说明》时，把"要写进文档的说法"逐条交给 Codex 核对，它指出两处退出码与代码不符。核对后发现是**真实缺陷**，先修再写文档。

## 一、两个缺陷

### 1. `--shot clipboard` 成功却返回 1

```swift
// Screenshot.capture(.clipboard) → (ok: true, file: nil, "已复制到剪贴板")
let r = Screenshot.capture(mode)
guard r.ok, let f = r.file else {          // ← 这里
    print("未截图：\(r.message)")
    exit(r.message == "已取消" ? 0 : 1)    // ← 复制成功也走到这，exit 1
}
```

剪贴板模式**本来就不产生文件**，却走了"必须有文件才算成功"的判定：脚本里一条成功的截图被当成失败，输出还是「未截图：已复制到剪贴板」——自相矛盾。

界面路径（`finishScreenshot`）一直是对的，只有 CLI 有这个问题。

**修复**：`clipboard` 模式在文件判定之前单独返回，成功与取消都 `exit 0`（取消不是错误）。

### 2. 子命令的 `--target` 缺值静默降级

```swift
// 修复前
if let t = args.firstIndex(of: "--target"), t + 1 < args.count { target = args[t + 1] }
```

`--shot full --target`（漏了值）不会报错，而是**沿用上次保存的目标**继续执行——这与 `--file` 的行为相反（1.3.7 已把 `--file` 改成 `exit 2`），结果是"以为投到 A，实际投到 B"，比直接报错危险。

`--transcribe` 同理：漏值会变成"不写笔记"，用户以为转写失败。

**修复**：两处都按 `--file` 的口径处理——给了 `--target` 却没给值（或下一个参数是另一个选项）→ `exit 2` + 明确提示 + 不产生任何副作用。

## 三、顺带修正的文档错误

写《应用说明》时按代码逐条核对，改掉了旧版里几处**会误导人**的说法：

| 旧说法 | 实际情况 |
|---|---|
| 「音频不落盘」 | 1.3.11 起先写 CAF 再转写；成功删、失败留 7 天 |
| 「网络请求：无」 | 程序不上传任何内容，但首次语音转写可能向 Apple 请求语言资源（下载系统语音模型） |
