# ObsidianDrop 1.3.12（构建 16）— 「一直卡在转写收尾中」

一句话：**转写其实早就结束了，是界面被一条迟到的进度回调重新画成了「收尾中」，然后再也没有事件来更新它。**

- 交付：`dist/ObsidianDrop-1.3.12.dmg`（264K）
- SHA-256：`af4daa646673146c1163c4a353570923076a90302e0091f052cdd16f4202632a`
- 已安装：`~/Applications/ObsidianDrop.app`

---

## 一、为什么「一直」收尾

收尾阶段（系统还在消化最后一批音频）后台每 0.3 秒推一次进度。这一轮的时间线是：

```
T+0.0s  收尾开始，后台定时器每 0.3s 发一条 finishing 进度
T+4.0s  finalize 返回，转写结果已经完整（比如 278 字）
T+4.0s  发出「完成」回调，主线程开始写笔记
T+4.3s  队列里最后一条 finishing 进度被执行
        → 界面被画回「收尾中」
        → 之后再也没有任何进度或完成回调
        → 看起来就是永久卡住
```

关键点：**「完成」和「进度」是两条不同的路径投递到主线程的，先后顺序没有保证**。
写笔记又是在主线程同步做的（几十毫秒到几秒），给了迟到进度足够的时间挤到它后面。

而这条进度回调**没有任何「这一轮是不是已经结束了」的校验**——1.3.11 及以前都没有。

## 二、同样的现象还有第二个来源

写笔记（复制附件、生成 frontmatter、落 md）是在 `memoDone` 里、**界面重绘之前**同步执行的：

```swift
// 1.3.11
let out = try Filer(vault: Cfg.vault).memo(...)   // ← 主线程，可能几秒
dropView.renderMemo(.idle, ...)                   // ← 到这才重绘
```

库在 iCloud 上、或附件较大时，这几秒里窗口既不响应、又还显示着「收尾中」——
和转写卡死在观感上完全一样。

## 三、改了什么

### 1. 每个回调都带「轮次编号」（主修）

```swift
protocol MemoSink {
    func memoProgress(_ p: TranscribeProgress, run: Int)
    ...
}

// 接受条件：编号等于当前轮，且本轮尚未收尾
enum MemoGate {
    static func accepts(run: Int, current: Int, stateIsIdle: Bool) -> Bool {
        run == current && !stateIsIdle
    }
}
```

每点一次「灵感」`memoRunID += 1`，所有进度/音量/完成回调都带上它。
上一轮的、以及本轮已经结束之后的回调，一律丢弃。判断逻辑抽成了纯函数，自检里直接测（4 条）。

### 2. 写库移出主线程，并给一个明确状态

- 先进「**归档中 · 已识别 312 字**」（转圈环 + 写入本机库），界面立刻响应；
- `Filer(...).memo(...)` 挪到后台任务，完成后再回主线程闪「灵感已归档」；
- 归档期间若用户又开了一轮，完成回调不会去改界面（编号已变）。

### 3. 识别调用加超时兜底

`analyzeSequence` 本身不设上限，真机上语音服务异常时可能永不返回，界面就永远「识别中」。
现在按音频长度给上限（`clamp(秒数/8, 90s, 20min)`），超时带着已出的文字收工。

### 4. 收尾超时按音频长度算，不再写死

实测：3 分钟音频收尾 5.5 秒，48 分钟音频收尾 14.8 秒。改成
`clamp(秒数/20, 15s, 180s)`——短录音不会白等，长音频也不会被砍掉尾巴。

### 5. 新增落盘日志（这次真正能定位的东西）

```
~/Library/Logs/ObsidianDrop.log
```

关键节点全部写文本，超 200 KB 自动重来：

```
[11-04 20:56:13.012] 录音开始：录音-20261104-205613.caf，run 3
[11-04 20:56:33.884] 录音结束：墙钟 20.8s，文件 20.7s，4234240 字节，写失败 0 次，峰值 62%
[11-04 20:56:34.101] 识别完成：用时 0.4s，已出 5 字
[11-04 20:56:36.902] 收尾：用时 2.8s（限 15s），正常，字数 96
[11-04 20:56:36.905] 转写完成：音频 20s，产出 96 字
[11-04 20:56:37.210] 本轮结束：run 3，96 字，时长 20.7s，正常
[11-04 20:56:37.268] 归档完成：10-项目/测试/2026-11-04 灵感 20-56.md
```

`NSLog` 走的是系统统一日志，在你机器上不好取；这个文件可以直接发过来。

顺带：迟到回调被丢弃时也会记一条（同一轮只记一次），如果还有问题，日志里能直接确认
是不是同一类原因。

## 五、如果还卡

1. 打开 `~/Library/Logs/ObsidianDrop.log`（访达里按 `⌘⇧G` 粘贴这个路径）。
2. 看最后一行是哪个阶段：
   - 停在「识别完成」→ 收尾没走完（会写「收尾：超时」）；
   - 有「转写完成」但没有「本轮结束」→ 界面回调没到；
   - 有「本轮结束」但没「归档完成」→ 卡在写库（看库是不是在 iCloud/网络卷）。
3. 把这个文件发我即可，不用再描述现象。
