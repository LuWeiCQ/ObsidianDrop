2 搜索：库内 3ms，库外借 Spotlight

索引只做一件事——把每篇笔记的小写 UTF‑8 字节留在内存里，匹配交给 memmem。压测过 String.contains（3000 篇 180ms，不可用）、SQLite FTS5 和中文 bigram 倒排（多 60–100MB 内存换 5ms，不划算），最后选了最土也最快的那条。

场景实测说明
3000 篇 / 10MB 单次查询3.1 msData + memmem，索引常驻约 10MB
增量刷新（mtime + size 比对）9 msApp 常驻时每次搜索前刷一次，刚存的笔记立刻搜得到
真实库 51 篇首建31 ms全量；进程退出即释放
库外文件≤ 1.2 s 硬超时NSMetadataQuery，拿不到就返回空，绝不卡住输入框

3 看板：数量、成功率、耗时、打开率

「打开 → 使用看板…」是一个独立窗口（不是浮层），停下来看数据时不该跟着菜单栏收起。四个指标卡 + 近 7 日柱状 + 最近投递，点任意一条直接跳到那篇笔记。

口径

只统计「真的投进库」的动作

拖拽 / 语音 / 截屏三类算投递，搜索与打开不算——混进去会把成功率稀释成一个没有意义的数字。p95 只在样本 ≥30 时给，否则等于最大值。

隐私

埋点里没有内容

只记次数、耗时、成功失败、AI 状态；目录与笔记路径加盐 SHA256 后取前 8 位。跳转另存一张只在本机的 jump.json，--metrics --raw 不输出它。

4 入库前 AI：唯一挂载点，失败就原样入库

AI 只挂在 MemoArchiveQueue.archive() 一处——界面回调会被看门狗、启动补归档、轮次顶掉三条路径绕过，挂那儿必然出现「有时过了 AI、有时没过」且看不出来。

状态含义写入笔记的内容
off没启用或没配 Key与 1.3.15 完全一致，不写任何 AI 字段
pending已入队，还没结果—
done成功摘要 / AI: "模型"（耗时），标题用 AI 生成的，tags 合并去重
skipped超时 / 4xx / 5xx / 无 Key只写一行 AI: 跳过（本次未处理，正文为原始转写），正文照旧
为什么结果要写回 pending：进程若在「AI 成功」与「写笔记」之间被杀，重启后重试会读到 done 直接复用结果——否则同一条灵感会被计费两次。预算是绝对的 12 秒，超时先取消请求再降级，不让网络状况决定你等多久。

Key 存在系统钥匙串（服务 com.lw.obsidiandrop.ai），地址只接受 https，本机 127.0.0.1 例外（供 Ollama / LM Studio），拒绝带 query、fragment、用户名密码的写法。设置窗口里可以「拉取模型列表」直接切换模型，也能一键测试连接。

5 性能：九个热点

编号原来现在
P1每条日志 new 一个 DateFormatter + open/seek/close格式化器与句柄常驻，写日志只剩一次 write
P2每次开菜单都扫 10-项目按目录 mtime 缓存，项目没变就不扫
P313 处调用点整套重建 NSMenu（有一处在转写进度里每 0.3s 触发）只建一次，之后改 title / state / isEnabled
P4换屏后窗口可能留在不存在的坐标监听屏幕变化，夹回可见区域
P6load(id:) 实为全量扫描，收尾时连调两次直读那一个 JSON
P7看门狗在主线程补归档（读盘 + 写笔记）移到后台，完成后再回主线程收尾
P8 / P9转圈每帧重绘整个视图；录音期每帧重建 NSImage只失效环那一小块；图标与标题按需才换

6 审查：两轮只读代码审查，19 项全修

功能跑通不等于可以交付。1.6.0 在打包前做了两轮独立只读代码审查（不碰代码，只给结论 + 行号），第一轮 13 项 P1 / 9 项 P2、无 P0；第二轮针对修复本身再查一遍，确认无新引入的 P0/P1，同时指出 5 项残留问题——都已按建议改掉。

问题为什么它不是「小毛病」现在
下拉期间误写「面板可见」ESC 收起后再点图标，面板以为自己是常驻浮窗，位置错乱只有 docked 模式才写偏好
拖动覆盖常驻坐标下拉里拖一下投放区，把常驻浮窗的位置也改了下拉不落坐标，标记位拦下
缺「点外部 / 切 Space 收起」下拉挂在那儿挡窗口，只能再点一次图标失活与切换空间都主动收起
搜索序号晚于防抖推进快速连打时旧查询能覆盖新结果文本一变立刻作废在途查询
索引读失败仍提交 stamp那篇笔记之后永远搜不到（因为「没变」）读失败保留旧 stamp，下轮重试
AI 重定向未校验来源接口被劫持时能把 Key 带到别的域名只允许同源重定向，跨源直接失败降级
AI 结果写回吞错崩溃后重试会重复计费，且日志里看不出来写回失败带原因记日志
看板主线程读 JSONL埋点攒到几 MB 后，打开看板会「卡一下」解析移到后台，回主线程只刷界面
AI 埋点与投递埋点重复计数一次投递算两次，「AI 完成」数字直接翻倍按 captureId 归并，ai 事件优先
打开率按次数算同一篇点三次算三次，能算出 300%按笔记去重，仍夹在 100% 以内
日界用 86400 秒硬减夏令时那天 23/25 小时，柱状图少一根、旁边翻倍按 Calendar 递推，自检里放了 2026-03-08 美东用例
「笔记写完、队列没删」崩溃窗口重启后补归档会再写一篇几乎一样的笔记落盘前写 .done 标记；标记没落盘的那一段，用「正文前 60 字 + 时间窗」在恢复路径查重
自检为什么从 140 涨到 155：每条修复都配了能真的失败的断言——比如夏令时那两条，用旧的「减 86400 秒」跑会得到 6 个日期、且 03-08 那个桶根本不存在；AI 去重那条，去掉归并就会从 1 变成 2。

8 已知限制

  • 本机（Mac mini）没有麦克风，录音链路只能用 --record-test / --ui-memo 验；真机录音请在 MacBook 上确认一次。
  • AI 需自备 Key。开着开关但没配 Key 时，每条都会走「跳过」，笔记与旧版完全一致。
  • Spotlight 依赖系统索引；索引没建好时库外结果为空，库内不受影响。
  • 看板从 1.6.0 开始积累数据，历史投递不回溯。
