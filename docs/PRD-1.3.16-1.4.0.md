## 1. 背景与问题

ObsidianDrop 解决的是「入口」问题：一条灵感出现在微信里、浏览器里、或你嘴里，等打开 Obsidian、想好放哪、起名、补 frontmatter，它已经凉了。1.3.x 把这一步压成「拖／截／说」一个动作。

但 1.3.15 有三个使用层面的缺口：

| 缺口 | 具体表现 | 代价 |
|---|---|---|
| **入口只有一条路** | 左键点菜单栏图标弹的是 16 项长菜单，找「灵感」要扫一遍 | 每次 2–3 秒；一天十次就是半小时 |
| **找不到已经进来的东西** | 只能打开 Obsidian 再搜，或记住文件在哪 | 归档后回头找要 5–20 秒，且经常放弃 |
| **菜单在长身体** | 16 个顶层项，5 个「打开…」、2 个转写入口平铺 | 认知负担随版本增长 |

同时，逐版修补留下了一批**只在特定路径才触发**的性能问题（日志每行开关文件句柄、归档结束扫两遍队列、看门狗在主线程写盘）。它们不影响功能正确性，但会让「卡一下」这种模糊体感反复出现。

## 2. 目标与非目标

### 2.1 目标（可量化）

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 从「想记」到「入口可达」≤ 1 秒 | 点图标到面板可交互的时间；人工计时 + 自检断言 |
| G2 | 从「想起关键词」到「打开那篇笔记」≤ 3 秒 | 输入到命中列表出现（目标 < 300 ms 体感），回车跳转 |
| G3 | 顶层菜单项 ≤ 7（1.3.16），加入搜索后 ≤ 8 | `menu.items.count` 自检 |
| G4 | 3000 篇笔记的库，单次检索 ≤ 10 ms | `--search` CLI 的 `query_ms` 字段 |
| G5 | 录音 5 分钟，稳态 CPU 与 1.3.15 相比下降 | Instruments 采样；不劣化 |
| G6 | 不新增任何第三方依赖，`./build.sh` 仍能一次编过 | 从干净 clone 构建 |

### 2.2 非目标（明确不做）

| 不做 | 理由 |
|---|---|
| 双向编辑 / 改写既有笔记 | 最高风险操作，产品红线 |
| 录音期间实时出字 | 会让 1.3.12–1.3.14 修过的竞态复现 |
| 云端转写 | 隐私定位；端上模型已够用 |
| 自建同步 | Obsidian 生态已有方案，重复造轮子 |
| 成为 Obsidian 插件 | 插件只能活在 Obsidian 窗口里，本产品要在任何 App 之上接受拖拽 |
| 全局热键（本版） | 双触发已覆盖「手不离开」；热键要额外处理冲突与权限，放 1.6.0 评估 |

## 3. 用户与场景

### 3.1 主要用户

| 画像 | 特征 | 核心诉求 |

| **P1 知识工作者**（主） | Obsidian 日常使用者，库 50–3000 篇；每天 3–10 次「零散东西入库」 | 入库不要打断当前工作；事后能找回来 |

### 5.4 搜索（1.4.0）

| 项 | 规格 |
|---|---|
| 数据 | 库内 `.md` 的 UTF-8 原文常驻内存；ASCII 小写副本懒建 |
| 检索 | 字节级子串匹配（`memmem`），中文天然支持 |
| 延迟 | 3000 篇 / 10 MB：单次 3–6 ms；建索引 330 ms（后台） |
| 刷新 | 面板展开前按 mtime+size 增量（3000 篇 9 ms）；按键不刷新 |
| 内存 | 常态 20–32 MB（3000 篇库） |
| 排序 | 标题命中 > 文件名命中 > 正文命中次数；同级 mtime 降序，`rel` 稳定 |
| 片段 | 命中位置前后 24 字；字节区间先对齐 UTF-8 边界 |
| 空关键词 | 不显示列表，只留投放区 |

**边界处理**

| 情况 | 行为 |
|---|---|
| `.icloud` 未下载占位 | 排除，不触发下载 |
| 符号链接（库内/库外） | 一律跳过 |
| 单文件 > 8 MiB | 只索引名称/标题，标 `too_large` |
| 二进制假 `.md` | 只索引名称 |
| 非 UTF-8 编码 | 正文跳过，文件名仍可搜 |
| 跨目录同名 | 各自独立，用相对路径区分 |

## 11. 使用看板（1.4.1，埋点与看板同版交付）

### 11.1 要回答的四个问题

看板不是「把数字排一排」。它只服务四个决策：

| # | 问题 | 数据能给的答案 | 决定什么 |
|---|---|---|---|
| Q1 | 这东西我到底在用吗 | 周入库条数、活跃天数 | 要不要继续投入 |
| Q2 | 哪一步在拖后腿 | 各阶段耗时 P50/P95、失败原因分布 | 下一版修哪里 |
| Q3 | 存进去之后我回头看吗 | 24h / 7d 回访率、搜索命中率 | 搜索值不值得做深、AI 摘要有没有用 |
| Q4 | AI 加进来到底赚不赚 | AI 处理率、降级次数、token 与耗时增量 | AI 默认开还是关 |

### 11.2 指标定义（必须先定死，否则数字会自相矛盾）

**北极星**：`WCN` —— 周成功入库条数（Weekly Captured Notes）。只有它值得一个季度一个季度地看。

**分析单位先定死**：一次用户动作 = 一个 `capture_id`。批量拖 3 个文件是 1 个 capture、3 个 note；成功率按 capture 算，备注数单列。不做这个约定，分子分母会不同单位。

| 层 | 指标 | 定义（复核后收紧） | 口径陷阱 |
|---|---|---|---|
| 效率 | 端到端耗时 | `accepted` → 笔记文件落盘（含转写、AI、写盘） | 从动作被接受开始算，不含用户发呆 |
| 效率 | 搜索到打开 | 首次按键 → `obsidian://` 发出 | 不含 Obsidian 启动时间 |
| 质量 | 成功率 | 终态为成功的 capture ÷ **accepted 的 capture** | 取消只在 `accepted` 之后发生才计失败；未接受就取消的不进分母 |
| 质量 | 短结果率（原称 0 字率） | 转写文本 < 10 字 ÷ **完成的转写尝试** | 分母只含「跑完的转写」，按录音 / 文件分层；转写报错、结果为空、结果过短三个计数分开统计，不合并 |
| 质量 | 积压 | `pending/` 条数、最老一条的年龄 | 大于 0 就是有东西没进库；这是首屏第一优先级 |
| 采用 | **应用内**回访率 | 24h 内由本应用打开过的笔记 ÷ **已满 24h 的 cohort** | ① 排除投递后自动打开（`from=after-drop`）；② 每篇按 capture_id 去重；③ 未满观察窗口的不进分母 |
| 采用 | 入口分布 | 拖入 / 截屏 / 录音 / 文本 占比 | 判断哪个入口值得优化 |
| 成本 | AI 调用 | 次数、token、估算费用、降级次数 | 本地模型记 0 成本，但记耗时 |

三条「不显示」规则（样本太少时宁可不说）：

1. 样本 < 30 不给百分位，只显示中位数、最大值与样本量 `n`。
2. 回访率在 cohort 未满窗口时显示「统计中」，不显示 0%。
3. 目标分布只在启用「AI 目标建议」后才出现（见 §12.5），否则它只是一张「你最近点在哪个目录」的图。

### 11.3 事件模型（埋点）

一条事件一行 JSON，追加写 `~/Library/Application Support/ObsidianDrop/metrics.jsonl`，权限 0600：

```json
{"v":1,"ts":"2026-11-05T15:20:03+08:00","ev":"drop","kind":"memo",
 "target_id":"t_7f3a91","bytes":184320,"chars":412,
 "ms":{"prep":820,"transcribe":9400,"ai":1180,"write":11},
 "ok":true,"err":null,"note_id":"00A1…",
 "ai":{"profile":"local-qwen","model":"qwen2.5:7b","in":860,"out":210,"fallback":false},
 "app":"1.5.0(24)"}
```

| 事件 | 触发点 | 关键字段 |
|---|---|---|
| `accepted` | 动作被接受（点了灵感、松手放下文件、按下截图确认） | capture_id / kind / target_id |
| `drop` | 同一 capture 的终态（成功或失败都记） | capture_id / kind / target_id / ms / ok / err |
| `open` | 用 `obsidian://` 打开了一篇（本应用发起的） | note_id / from（`after-drop` / `search` / `detail`） |
| `search` | 一次搜索被「用了」（按下回车） | query_len / hits / first_rank / ms |
| `ai` | 一次 AI 调用 | profile / model / in / out / ms / ok / err |
| `pending` | 队列变化（入队/出队/失败） | size / oldest_age_s |
| `config` | 配置变更（不含敏感值） | key / from / to |

**三条硬规矩**：

1. **绝不记正文**。只记长度、字节数、目标目录。日志里出现笔记内容即为缺陷。**目标目录名也算敏感**（可能含客户名）→ 事件里只写 `target_id`（相对路径的加盐哈希前 8 位），目录真名只在看板渲染时从库目录现读，永不落日志。
2. **写事件不能影响主流程**。落盘失败、磁盘满、文件被锁，一律吞掉错误并跳过，绝不因为埋点让一次投递失败。
3. **版本字段 `v` 必须存在**。老事件永远可读，新字段只增不改。

保留期 90 天，超出按周聚合后删除明细（保留 `metrics-weekly.json`）。提供「一键清空」与「导出 CSV」。

### 11.4 看板信息架构

```
┌ 使用概览 ───────────────────────── 近 7 天 ▾  [导出 CSV] ┐
│ ⚠ 2 条待归档（最老 3 小时）· 1 次失败 · AI 已暂停   [处理] │  ← 首屏第一行
├──────────────────────────────────────────────────────────┤
│  今日 6 条 ↑12%   成功率 97.4%   P50 1.1s（n=42）  回访 61% │
├───────────────────────────┬──────────────────────────────┤
│  每日入库（按类型堆叠）    │  状态分布（不是漏斗）        │
│  ▁▃▅▂▇▄▆                  │  已入库 38 ██████████████    │
│                           │  待归档 2  █                  │
│                           │  失败 1    █                  │
├───────────────────────────┴──────────────────────────────┤
│  目标分布 Top5          │  失败原因                │ AI 用量 │
├──────────────────────────────────────────────────────────┤
│  最近 50 条明细：时间 / 类型 / 目标 / 耗时 / 结果 / [打开] │
└──────────────────────────────────────────────────────────┘
```

> **为什么把漏斗换成状态分布**：真正的漏斗需要 `accepted → 终态` 的完整生命周期事件。首批只保证「终态正确」，用漏斗会画出假流失。状态分布不需要纵向可比，同样能回答「有多少东西没进去」。等事件模型跑稳一版再考虑漏斗。

| 区块 | 内容 | 交互 |
|---|---|---|
| 待处理条 | 待归档条数 / 最老年龄 / 失败数 / AI 暂停 | 直接跳到对应明细并支持「重试」「重新连接」 |
| KPI 行 | 今日入库、成功率、P50（附 n）、应用内回访 | 点卡片切到对应明细筛选 |
| 每日堆叠柱 | 7/30 天，按入口类型分色 | 悬停显示当日明细；点柱钻取 |
| 状态分布 | 已入库 / 待归档 / 失败 / 取消 四条横条 | 点击某条只看该状态的条目 |
| 目标分布 | Top5 目录横条 | 点击筛选 |
| 失败原因 | 权限 / 磁盘 / 库不存在 / 写入冲突 / AI 降级 | 点击展开原始错误（转写为空属质量指标，单列在 §11.2，不算失败终态） |
| AI 用量 | 调用数、token、均价、降级次数 | 只在启用 AI 后出现 |
| 明细表 | 最近 50 条 | 行尾「打开」直接跳 Obsidian；右键复制 ID |

**设计约束**：不引入图表库（项目零依赖），柱状/漏斗/折线都用 `NSView` 自绘，约 200 行。

### 11.5 隐私

看板数据**全部在本机**，与 1.3.x 的「不上传」一致：

- 不联网、不埋第三方、不写笔记正文
- 首次打开看板给一行说明：「这里只记录条数与耗时，不记录你写了什么」
- 「清空统计」放在看板右上角，二次确认

## 12. AI 前置处理（1.5.0）

### 12.1 它插在哪一步

```
转写文本 / md 正文 / 剪贴板文本
        │
        ▼
  ① 预处理      去噪、合并空白、截断到 6000 字
        │
        ▼
  ② 模型调用    结构化输出（标题 / 摘要 / 标签 / 目标建议）
        │
        ▼
  ③ 校验        JSON schema + 长度 + 标签白名单
        │
        ▼
  ④ 合并       写进笔记 frontmatter 与正文
        │
        ▼
  ⑤ 落库       仍走原来的 Filer，不新开写入路径
```

**关键设计**：AI 只产出「建议字段」，**最终写入仍走原有 `Filer`**。这样 1.3.14 建立的原子写入、pending 队列、看门狗全部继续有效，AI 挂了不影响落库。

**挂载点（复核后修正）**：AI 必须挂在 `MemoArchiveQueue.archive()` 这个**唯一归档出口**内，不能挂在 UI 的 `acceptDone` 上。因为文字转写完成后已经先落在 pending 队列，看门狗与启动补写也会归档同一份结果；只挂 UI 会出现「看门狗写了原文、UI 的 AI 结果因 pending 消失被静默跳过」。详见技术方案 §13.1。

### 12.2 输出契约

```
系统提示：你是 Obsidian 笔记结构化助手。只输出 JSON，不要解释。
用户输入：<content>…原文…</content>
```

```json
{"title":"预焙阳极焙烧曲线调整","summary":"讨论三段升温速率与 60 万吨产能的匹配。","tags":["预焙阳极","焙烧","工艺"],"target":"10-项目/强强碳素"}
```

| 字段 | 约束 | 超限处理 |
|---|---|---|
| `title` | ≤ 24 字，无换行，不以标点结尾 | 截断到 24 字 |
| `summary` | ≤ 80 字，无换行 | 截断 |
| `tags` | 3–6 个，每个 ≤ 8 字，只允许中文/英文/数字/`-` | 过滤超限项，少于 3 个则放弃标签 |
| `target` | 必须是库里已存在的相对路径 | 不存在则**忽略**，用当前目标 |

`target` **不自动采用**。自动分类错的代价（东西进了错的目录、你找不到）大于收益（少点一次菜单）。模型给的建议只作为正文里的一行文字，改不改由人点——见 §12.5。

### 12.3 失败即降级，不阻塞

| 失败点 | 行为 | 用户感知 |
|---|---|---|
| 网络不通 / 超时 | 用原文入库，标 `ai: skipped` | 正常出笔记，frontmatter 少三个字段 |
| 鉴权失败 401 | 降级 + 设置里红点提示 | 同上 |
| 模型返回非 JSON | **不重试**，直接降级（请求已发出，重试只多计一次费） | 同上 |
| 校验不过（标签全超限） | 只丢标签，保留标题与摘要 | 同上 |
| 触发护栏（超次数/超长度） | 本次跳过 AI | 同上 |

**任何情况下，AI 环节不能导致「这次投递失败」。** 这是本节的验收红线。

### 12.4 模型配置管理

| 能力 | 规格 |
|---|---|
| Provider | ① OpenAI 兼容（自定义 Base URL + Key + 模型）② 本地（Ollama / LM Studio，默认 `http://127.0.0.1:11434/v1`）③ 关闭 |
| 多套配置 | 可存多个 profile（如「本地 7B」「云端 mini」），命名、复制、删除 |
| 密钥 | 存 Keychain（`kSecClassGenericPassword`，service `com.lw.obsidiandrop.ai`，account=profile id）；**不写 UserDefaults、不写日志** |
| 连接测试 | 三步分别给结论：DNS/连通 → 鉴权 → 最小补全；每步显示耗时与错误分类 |
| 地址校验 | 拒绝带 query / fragment / userinfo 的 Base URL；远程只允许 https，http 只允许环回地址 |
| 输出脱敏 | `--ai-test`、日志、错误弹窗统一只输出 `scheme://host[:port]/path`，不输出响应体 |
| 模型切换 | 从 `/models` 拉列表（失败则允许手填）；下拉即切，切换后自动跑一次轻量探活 |
| 任务映射 | 摘要 / 标签 / 标题可分别指定 profile（默认同一个） |
| 护栏 | 单次输入 ≤ 6000 字、每日 ≤ 200 次、连续失败 3 次自动暂停并提示。计数**独立原子存储**，不复用统计日志（统计允许丢，护栏不能丢） |
| 隐私 | **默认关闭**。开启云端 profile 时必须勾选「文本将发送到 example.com」；本地 profile 不需要勾选也能开启 |

**连接测试的错误分类（决定提示怎么写）**：

| 现象 | 判定 | 提示 |
|---|---|---|
| 无法解析主机 | DNS 失败 | 「域名解析不了：检查地址拼写或网络」 |
| 连接超时 8s | 可达性失败 | 「连不上：地址或端口是否正确？本地服务起了吗？」 |
| 401 / 403 | 鉴权失败 | 「Key 无效或没权限」 |
| 404 | 路径错 | 「Base URL 通常以 /v1 结尾」 |
| 200 但返回结构不符 | 协议不符 | 「这个地址不是 OpenAI 兼容接口」 |

### 12.5 目标目录建议：只展示，不自动采用（复核后改）

原方案写「连续 3 次建议到同一目录才采用」。复核第 20 条指出这个条件没有置信度来源：模型不返回 confidence，而当前的投递目标又会被喂回模型，形成自我强化——错一次就可能连着错，且用户不知道是谁改的目录。

**改为**：

- AI 可以在笔记里写一行「建议放到：10-项目/强强碳素」（作为正文的一部分，可删）
- **不自动改变投递目标**。要改，用户自己点那一行或从菜单改
- 设置里不再提供「自动分类」开关（本版没有这个能力，就不给这个开关）

理由：分错目录的代价是「东西找不到了」，比多点一次菜单严重得多。这个功能可以以后基于真实的「用户采纳率」再做，届时用数据说话。

### 12.6 验收

| 断言 | 方式 |
|---|---|
| prompt 渲染正确（含分隔符、长度截断） | 纯函数 + 自检 |
| 非 JSON / 缺字段 / 超长字段的处理 | 自检注入假响应 |
| 失败必降级：网络失败后仍生成笔记且带 `ai: skipped` | `--ai-run` + 断网注入 |
| 护栏计数：第 201 次不再调用 | 自检 |
| 连接测试四类错误的分类正确 | 自检注入假 URL |
| Keychain 读写（不落到 preferences） | 自检（临时 service） |
| 事件里不出现正文 | 自检扫描 metrics.jsonl |

CLI：

```
--ai-test <profile>              连接测试，输出 JSON（steps[].ok / ms / err）
--ai-run <文件> --profile <id>   跑一次处理，输出结构化结果（不落库）
--metrics [--days N] [--json]    看板数据的文本版
--metrics --export <csv>         导出
--dashboard                      打开看板窗口
```

## 13. 这两块对既有承诺的影响（必须明说）

1.3.x 的 README 写着「**无网络请求**」。加了 AI 之后这句话只有在 AI 关闭时成立。

**改法**：把承诺拆成两条可验证的：

- 音频与附件**永不出本机**（转写仍走系统端上模型）
- 文本仅在用户显式开启 AI 后发送到**用户自己配置的**服务；默认关闭；本地模型可做到全链路离线

发布说明、设置面板、首启提示三处措辞必须一致，不能一处说「不上传」、一处默认开着。
