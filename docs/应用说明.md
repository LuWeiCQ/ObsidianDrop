# ObsidianDrop 应用说明

> 版本 1.7.0（构建 25）｜2026-11-10｜macOS 13+，仅 Apple Silicon
> 源码：`Sources/main.swift`（单文件，7879 行，无第三方依赖）
> 配套：`使用说明.md`（怎么用）、`releases/修复说明-1.3.6 ~ 1.3.15.md`（每版改了什么）、`迭代建议-提效路线.md`（后续规划）

## 一、它是什么

一个**菜单栏常驻的「落点」**：把库外那些"还没进知识库"的东西——一个文件、一张截图、一句刚说出口的话——用最短路径送进 Obsidian，并顺手补齐元数据与笔记。

价值不在"多一个功能"，而在把"记录"这一步的成本压到接近零：不打开 Obsidian、不选目录、不写 frontmatter、不想文件名。

```
拖文件 ─┐
截  图 ─┼→ 悬浮小窗（常驻桌面）→ 判定目标 → 复制/落盘 → 写笔记（frontmatter + wikilink）→ 进库
说  话 ─┘                                    ↑
                                    菜单栏可随时切换投递目标
```

## 二、边界：它是什么，不是什么

| 常见期待 | 实际情况 | 原因 |
|---|---|---|
| "是一个 Obsidian 插件" | **不是**。独立 macOS 应用，不装进 `.obsidian/plugins/`，不读不写 `.obsidian/` | 插件只能活在 Obsidian 窗口里；本应用要在**任何** App 之上接受拖拽、截图、录音 |
| "在 Obsidian 里能点按钮" | 没有按钮，也不需要。靠**文件契约**生效，Obsidian 被动索引 | 少一层依赖，插件冲突与版本升级都不影响它 |
| "能整理、能改我的笔记" | **只新建，不改既有笔记**。写入范围只有本次投递产生的那一篇 | 自动改写用户笔记是最高风险操作 |
| "云端转写，识别更准" | 端上转写（macOS 26 `DictationTranscriber`），音频不离开本机 | 隐私优先；代价是识别质量受系统语言包影响 |
| "装在 Intel Mac / Windows 上" | 仅 arm64 + macOS 13+；语音需 macOS 26+ | 交付范围就是 Apple Silicon |
| "所有 CLI 参数错误都返回 2" | 只有 `--file` 有完整校验；`--shot` / `--transcribe` 的 `--target` 缺值自 1.3.15 起也返回 2 | 逐条修，不假装一次到位 |

## 三、插件功能说明：它是「文件生产者」，不是插件

### 3.1 四层契约

它与 Obsidian 之间**没有 API 调用**（除打开笔记那一下），全部通过"文件 + URI"两层完成：

| 层 | 契约 | 用到的 Obsidian 能力 | 依赖插件？ |
|---|---|---|---|
| 数据层 | 在库目录里写 `.md` 与附件 | 库扫描、附件解析、属性（frontmatter）、标签、`![[...]]` 嵌入 | 否 |
| 命名层 | `YYYY-MM-DD 名称.md`；附件同名加日期前缀 | 按文件名排序即时间线；双链按**路径**解析，重名不串链 | 否 |
| 导航层 | `obsidian://open?vault=<库目录名>&file=<相对路径>` | Obsidian 官方 URI 协议 | 否 |
| 组合层 | 固定字段：`类型` / `目标` / `归档时间` / `创建时间` / `时长` / `文件` | Dataview 查询、Templater 复用、Tasks 扫描 | 用户自选 |

**一句话**：它负责"把东西送进库、把元数据填好"，Obsidian 及其插件负责"把这些东西用起来"。两者靠**字段契约**解耦——即使明天卸载 ObsidianDrop，已归档的笔记与附件仍然完整可用。

### 3.2 Obsidian 本体负责什么

附件解析、wikilink 解析、属性编辑器、标签索引、搜索、反向链接、图谱、正文编辑——**全部由 Obsidian 完成**。本应用只保证三件事：文件相对路径正确、frontmatter 字段稳定、链接文本与真实路径一致。

它**不生成笔记之间的双链**，只做附件嵌入。理由：图谱上不该出现一团"归档"星云，笔记之间的关系应该由人建立。

### 3.3 与常见插件的分工

| 插件 | 它更擅长 | 与本应用的关系 | 建议 |
|---|---|---|---|
| **Dataview** | 把散落笔记变成视图 | **最强组合**。直接查本应用写入的字段，无需配置 | 见 3.4 |
| **Templater** | 在 Obsidian 内新建笔记时的结构 | 分工：Templater 管"库内新建"，本应用管"库外进来" | 别让模板自动重处理本应用生成的文件（可能覆盖追加正文） |
| **QuickAdd** | 库内快速捕获（需先切到 Obsidian） | 平行的另一条入口 | 正在用 Obsidian → QuickAdd；在别的 App 里 → 本应用 |
| **Tasks** | 待办汇总 | 当前不生成任务行 | 需要时自行在转写稿里加 `- [ ]`；"自动拆行动项"在路线图 |
| **Advanced URI** | 更复杂的 URI 动作（追加、执行命令） | 本应用只用官方 `obsidian://open`，**不依赖** | 装了它的用户可以把它接在本应用后面做后续动作 |
| **Periodic Notes / 日记** | 日记与周期笔记 | 路线图里的"当日索引"会往日记文件追加一行 | 追加而非重写，见迭代建议 A3 |
| **同步方案**（iCloud / 官方 Sync / Remotely Save） | 同步 | 无冲突：本应用只做本地写入，落盘即完成 | 同步交给 Obsidian 侧，本应用不造第二套 |

### 3.6 为什么不做成 Obsidian 插件

| 做成插件 | 现在这样 |
|---|---|
| 只能在 Obsidian 前台使用 | 任何 App 上方都能拖、能截、能录 |
| 受插件 API 与版本变动影响 | 只依赖文件系统与官方 URI |
| 需要用户装、开、配 | 装完即用，菜单栏一个图标 |
| 拿不到系统级能力 | 截图、麦克风、外部拖拽全是原生 AppKit |

## 四、功能清单

### 4.1 文件归档

- 拖文件 / 文件夹到浮窗 → **复制**进库 + 生成笔记；源文件只读，不移动、不改名
- 多文件一次拖入：逐项处理，单个失败不中断其余，逐项报 `✓/✗`
- 重名自动加 `-2`、`-3`（先查后写，单实例顺序投递下不会覆盖；多实例并发无原子保证）
- 落点：项目目标 → `10-项目/<项目>/文档/`；其他 → `附件/YYYY-MM/`；**笔记本身放在所选目标目录**
- 呈现方式：图片/PDF 直接嵌入；普通文件给「打开 xxx」链接；文件夹只记路径与文件数（不生成 wikilink）
- 笔记写失败 → **先删刚复制的附件**再报错，不留孤儿文件，重试不会重复

### 4.2 截图归档

| 菜单项 | 行为 |
|---|---|
| 区域截图并归档 | 拖选区域 → PNG 进库 + 笔记 |
| 整屏截图并归档 | 主显示器整屏，不弹框，适合快捷键/定时任务 |
| 窗口截图并归档 | 点选一个窗口 |
| 区域截图到剪贴板 | 只进剪贴板，**不入库** |

菜单/浮窗路径会先临时收起浮窗（等 0.3 秒）再拍，不会把自己拍进去，且不改写「面板可见」偏好；命令行路径没有窗口，不做收起动作。截图取消不产生任何文件。

### 4.3 语音转文字（端上）

| 入口 | 适用 | 说明 |
|---|---|---|
| 浮窗「💡 灵感」 | 现场说话 | **不限时长**，点「结束」才停并转写（build 23 起） |
| 菜单「转写音频文件…」 | 已有音频 | 同样不限时长；wav / m4a / mp3 / aiff 等 |
| 菜单「转写剪贴板里的音频」 | 文件面板里被置灰的文件 | 访达 `⌘C` 复制后直接转，绕开系统面板判定 |
| `--transcribe <音频>` | 脚本/批处理 | `--out` 另存文本，`--target` 直接落笔记 |

链路：录音**先落盘** CAF → 关文件 → 按文件转写 → 结果先写 pending → 写笔记成功后才清理。任何一步失败，音频与文字都还在。

### 4.4 投递目标

- 菜单「投递目标」：`00-收件箱` + 扫描 `10-项目/` 下所有项目 + `20-领域` / `30-资源`
- 每次展开菜单都重新扫描，**运行中新建的项目立刻出现**
- 目标必须是库内相对路径：绝对路径、`~` 开头、含 `..`、解析后越出库（含软链指向库外）**整次拒绝**

### 4.5 状态与反馈

- 录音中：音量呼吸 + 计时（不显示实时文字，见第十一节）
- 转写中：阶段（准备/转写/收尾/归档）+ 已出字数 + 剩余时间 + 百分比环
- 完成：闪「灵感已归档」
- 卡住：主线程心跳（每 5 秒）+ 看门狗（20s 警告 / 30s 提示 / 150s 强制恢复界面，后台真出结果仍归档）
- 启动时若有上次残留的待归档结果，自动补写并在界面提示一次

### 4.6 菜单一览

| 菜单项 | 说明 |
|---|---|
| 显示/隐藏 投放窗口 | 悬浮窗显隐 |
| 把窗口移到右下角 | 位置跑偏了拉回来 |
| 窗口置于底层 | 不挡其他窗口（可勾选） |
| 截图 ▸ 区域/整屏/窗口/剪贴板 | 见 4.2 |
| 灵感（录音） | 标题随状态变化：开始 / 结束 / 转写中 |
| 转写音频文件… / 转写剪贴板里的音频 | 见 4.3 |
| 投递目标 ▸ | 见 4.4 |
| 打开 Obsidian / 库目录 / 附件目录 | 一键定位；「打开 Obsidian」只启动 App，不一定切到指定库 |
| 打开运行日志 / 复制日志路径 | 日志在 `~/Library/Logs/ObsidianDrop.log` |
| 投递后打开新笔记 | 可勾选；走 `obsidian://open` |
| 开机自动启动 | 走 `SMAppService`，不写 LaunchAgents |
| 退出 ⌘Q | — |

浮窗**右键**弹出的是同一份菜单，不用每次都去菜单栏。

### 4.7 偏好项（`defaults read com.lw.obsidiandrop`）

| `targetRel` | 当前投递目标（库内相对路径） | `00-收件箱` |
| `panelX` / `panelY` | 悬浮窗位置 | 右下角 |
| `panelVisible` | 悬浮窗是否显示 | 显示 |

## 五、数据流与落盘结构

### 5.1 一次文件归档

```
源文件（只读）
   │ 复制
   ▼
库/附件/2026-11/2026-11-05 会议通知.pdf      ← 附件
库/00-收件箱/2026-11-05 会议通知.md          ← 笔记（frontmatter + 嵌入）
```

顺序：先复制附件 → 再原子写笔记。笔记写失败则删除刚复制的附件。

### 5.2 一次语音归档

```
麦克风 → recordings/录音-20261105-092041.caf（边录边写）
   → 转写 → pending/<UUID>.json（.tmp→rename，0600）
   → 写笔记成功 → 删 pending + 删内部录音
        └ 失败 → 两者都保留，弹窗给「复制文本」，下次启动自动补写
```

刻意如此：**先确认落盘，再交付；先确认写成功，再清理。** 1.3.13 及之前是反的，结果一丢，文字和录音同时没了。

例外要说清：0 字 / 转写失败 / 取消时**不写 pending**，直接保留录音；用户自己导入的音频文件**从不删除**。

### 5.3 盘上都有什么

| 位置 | 内容 | 生命周期 |
|---|---|---|
| `~/Obsidian/Main/00-收件箱/` | 笔记 | 永久 |
| `~/Obsidian/Main/附件/YYYY-MM/` | 附件 | 永久 |
| `~/Obsidian/Main/10-项目/<项目>/文档/` | 项目附件 | 永久 |
| `.../Application Support/ObsidianDrop/recordings/` | 内部录音 | 成功即删；失败保留 7 天后清理 |
| `.../Application Support/ObsidianDrop/pending/` | 待归档文字（JSON，目录 0700、文件 0600） | 写成功即删；**不自动过期**，启动/看门狗各补一次（每次最多 5 条） |
| `~/Library/Logs/ObsidianDrop.log` | 运行日志 | 超 512 KB 删除重建 |

```yaml
> - 大小：182 KB
> - 存放位置：`附件/2026-11/`，会随库同步到手机
> - 由 ObsidianDrop 于 2026-11-05 09:12:03 投递到「00-收件箱」

```

### 6.2 灵感速记

```yaml
---
类型: 灵感速记
创建时间: 2026-11-05 09:20:41
时长: 0:27
目标: 00-收件箱
转写: 端上本机（DictationTranscriber / 中文）
tags:
  - 灵感
  - 收件箱
---

# 灵感 2026-11-05 09:20:41

（正文按空行分段）

> [!note] 录制信息
> - 时长：0:27
> - 转写：Mac 本机完成，未上传云端
> - 由 ObsidianDrop 于 2026-11-05 09:20:41 录在「00-收件箱」
```

**字段契约**：`类型` 与 `目标` 是稳定字段，可被 Dataview/脚本依赖；其余字段只增不改。
**YAML 注意**：只有 `tags` 做了标量转义；`文件` / `目标` / `来源目录` 是直接插入的，路径里含 `:`、`#` 等特殊字符时可能破坏 YAML——这是已知限制，见第十一节。

## 七、命令行参考

```bash
OBS=~/Applications/ObsidianDrop.app/Contents/MacOS/ObsidianDrop

$OBS --file <路径...> [--target <目标>] [--vault <库>] [--json]   # 归档
$OBS --shot full|area|window|clipboard [--target <目标>]          # 截图（clipboard 不入库）
$OBS --transcribe <音频> [--target <目标>] [--out <文件>]          # 转写
$OBS --login on|off                                              # 开机自启
$OBS --vault <库>                                                # 本次进程换库，不写偏好
```

### 7.1 退出码（**按子命令分别约定，不是全局协议**）

| 命令 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| `--file` | 全部成功 | 全部失败 / 目标非法 / 库不存在 | 用法错误、未知选项、缺值、无路径（**不写任何文件**） | 部分成功 |
| `--shot` | 成功（取消也算 0；`clipboard` 复制成功 0） | 截图失败（多为没有屏幕录制权限） | 参数非法 / `--target` 缺值 | — |
| `--transcribe` | 成功 | 无语音 / 失败 / 系统 < 26 | 缺参数 / `--target` 缺值 | — |
| `--self-test` | 全过 | 有失败 | — | — |
| `--audio-check` | 有可用输入设备 | 没有 | — | — |
| `--ui-memo` | 归档并复位 | 中途失败 | 超时或看门狗恢复 | — |

`--file` 加 `--json` 输出 `{ok, partial, total, succeeded, failed, exit_code, items[], failures[]}`。

### 7.2 诊断命令

```bash
$OBS --audio-check [--json]        # 五路探测：AVFoundation / CoreAudio / 默认输入 / 引擎格式 / TCC 权限
$OBS --record-test <音频>           # 按真实录音的 tap 参数写文件再转写，验证录音链路
$OBS --render-preview <目录>        # 面板各状态离屏渲染 PNG，验证排版
$OBS --self-test                   # 内置自检（209 项），不启动 UI、不碰真实库
$OBS --ui-memo <音频> --vault <临时库>  # 走完整界面链路并自动退出（0/1/2 见上表）
bash scripts/regression.sh         # 隔离库回归（56 项）
```

故障注入（仅验收用）：`OBSIDIANDROP_DROP_DONE=1`（模拟结果丢失）、`OBSIDIANDROP_DELAY_DONE=22`（结果迟到 22 秒）、`OBSIDIANDROP_STALL_SECONDS=25`（调小看门狗阈值）。

| 打包 | `./package-dmg.sh` |

## 九、安全与隐私

| 项 | 做法 |
|---|---|
| 路径越界 | `VaultGuard` 先词法规范化、再解析软链，目录创建前后各校验一次；库内软链指向库外直接拒绝 |
| 源软链 | 解析到真实对象后复制独立副本，库里不会出现指向库外的链接 |
| 写入范围 | 只新建本次投递的笔记与附件；不读不写 `.obsidian/` |
| 内容外传 | **程序没有任何上传实现**（代码中无 URLSession）。首次语音转写可能向 Apple 请求语言资源（下载系统语音模型），除此之外无网络访问 |
| 语音 | 端上识别，音频不出本机；成功后删除内部录音 |
| 中间态 | 录音与待归档文件都在用户私有目录，权限 0600/0700 |
| 日志 | 只记流程与计数，不记笔记正文 |

## 十一、已知限制

| 限制 | 影响 | 备注 |
|---|---|---|
| 超长录音的收尾要等 | 录音不限时长，转写收尾按音频长度算 | 1 小时约 1 分钟；收尾上限 15 分钟 |
| 录音期间不显示实时文字 | 只看到音量与计时 | 1.3.11 起为稳定性取舍 |
| 语音仅 macOS 26+ | 13–25 只能归档与截图 | 依赖系统 `DictationTranscriber` |
| 仅 arm64、未公证 | Intel 机不可用；首次打开需右键 | — |
| 无全局快捷键 | 每次要移到菜单栏点两下 | 已列入迭代 A1 |
| 无多库 UI 切换 | 只能 `--vault` 临时覆盖 | 已列入迭代 B2 |
| 模板写死 | 不能自定义笔记结构 | 已列入迭代 B4 |
| 重名检测非原子 | 多实例并发可能撞名 | 单实例使用无影响 |
| `obsidian://open` 用库目录名识别库 | 两个同名库会开错 | Obsidian URI 协议本身如此 |
| YAML 只转义 `tags` | 特殊目录名可能破坏 frontmatter | 已列入待修 |
| pending 不自动过期 | 长期失败会堆积 | 每次启动补归档最多 5 条 |
